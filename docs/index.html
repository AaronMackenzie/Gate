What this shows

The two strategy rules from the Python scripts, replayed on past prices so you can see where they would have bought and sold. The scripts themselves poll a live Zerodha Kite feed every 1 to 5 minutes; that cannot run without a broker session, so this is a simulation.

How the simulation works

Long only, one position at a time, all-in or all-out. By default a signal on one bar is filled at the next bar's close. Prices are daily closes, not the 5-minute candles the scripts read, and there is no slippage, tax or short selling.

How to read it

Compare the amber equity line with the dashed buy-and-hold line. Then switch to the synthetic random walk: it has no pattern to find, so rules like these should not beat holding there except by luck. Change the seed to see how much luck alone can do.

Prices: the real series is GLD, an SPDR gold ETF listed in the US (5,123 daily closes, 2004-11-18 to 2025-03-31), copied from the Gate-2.0 data folder. The scripts trade GOLDBEES, a gold ETF on India's NSE, which tracks gold in rupees. GLD follows the same metal in dollars, so it is a stand-in, not the same instrument. The synthetic series is a seeded geometric random walk (daily drift 0.03%, volatility 1%). Past results do not predict future ones, and one price history says very little. This is not investment advice.
02 · The repository

The four scripts

What each file does, and whether it can run. None of them were run against Zerodha: they need a live logged-in session and place real orders.

FileWhat it doesStatus
kit_trade.pySmall unofficial Zerodha Kite client: KiteApp with historical data, quotes, orders, positions, margins, plus get_enctoken() for a password login.Was a syntax error (body of historical_data not indented). Fixed; checked offline with a mocked HTTP session.
ApiCommands.pyA cheat sheet of calls: margins, orders, positions, instruments, quotes, historical candles, place, modify and cancel an order.Import fixed. Order examples now run only if KITE_PLACE_ORDERS=1.
MovingAverageCrossoverOnGOLDBEES.pyEvery 60 s fetches 7 days of 5-minute candles for instrument 3693569, keeps running lists of the 10- and 20-bar averages and signals a buy when the recent short average is above the long one.Import fixed; the buy order was missing and order was undefined; division by zero on startup. No exit logic exists.
StochasticOscillatorOnGOLDBEES.pyEvery 5 min computes %K over the closes in the 7-day window; buy 1 GOLDBEES above 80, sell 1 below 20 (intraday MIS product).Import fixed; window recomputed each pass; divide-by-zero guard; sleeps after errors.

Running the real scripts

They need your own Kite session token in the environment variable KITE_ENCTOKEN. Orders stay off unless you also set KITE_PLACE_ORDERS=1. Neither is possible from this page.

export KITE_ENCTOKEN=...     # your own session token, never commit it
python MovingAverageCrossoverOnGOLDBEES.py     # dry run: prints "DRY RUN", sends nothing
Security note. Earlier versions of two scripts had session tokens typed into the source. They are removed from the current files, but they remain in the Git history. Log out of Kite to invalidate them.
